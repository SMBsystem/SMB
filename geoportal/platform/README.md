# SMB Portal — единая платформа курсов (Supabase)

Все курсы в одном каталоге. Ученик входит по почте (или через Google) и попадает на курс:

* **по коду** — вводит код от преподавателя;
* **по запросу** — нажимает «Запросить доступ», вы одобряете в панели управления;
* **вручную** — вы одобряете запрос или выдаёте персональный код на 1 ученика.

Материалы курса лежат в **закрытом** хранилище Supabase: открыть их может только
записанный на курс ученик. Прямой ссылки на файл курса больше нет.

| Файл | Что это |
|---|---|
| `index.html` | Кабинет ученика: вход, «Мои курсы», ввод кода, каталог, запросы |
| `course.html?c=<адрес>` | Просмотр курса (грузит файл из закрытого хранилища) |
| `admin.html` | Управление (только админ): каталог курсов, запросы, коды, ученики |
| `config.js` | Адрес и публичный ключ Supabase |
| `app.js` | Общая логика и переводы KZ/RU |
| `../supabase/schema.sql` | Таблицы, права доступа, функции — запускается один раз |

## ⚙️ Подключение (один раз, ~15 минут)

1. **Аккаунт.** Зарегистрируйтесь на <https://supabase.com> → **New project**
   (регион — ближайший, например Frankfurt). Запишите пароль базы.
2. **База.** Слева **SQL Editor → New query** → вставьте весь файл
   `supabase/schema.sql` → **Run**. Должно быть «Success».
3. **Ключи.** **Project Settings → API**: скопируйте *Project URL* и ключ
   *anon public* в `platform/config.js`. (Ключ `service_role` никуда не вставляйте.)
4. **Адрес сайта.** **Authentication → URL Configuration**:
   * *Site URL* — адрес вашего сайта, например `https://smbsystem.github.io/SMB/geoportal/platform/`;
   * *Redirect URLs* — добавьте этот же адрес (и `http://localhost:8765/**` для проверки на компьютере).
5. **Станьте админом.** Откройте `platform/index.html` на сайте, войдите по почте.
   Затем в **SQL Editor** выполните:
   ```sql
   update public.profiles set role = 'admin' where email = 'showanchik@gmail.com';
   ```
   Обновите страницу — в шапке появится «👑 Басқару».
6. **Загрузите курсы.** В **Басқару → Курсы** у курса нажмите «⬆️ Загрузить файлы»
   и выберите `geotanu/geotanu.html` (для GeoTany) и `geonish/geonish.html` (для ГеоНИШ).
7. **Создайте коды.** Вкладка **Коды** → курс → тип → «🎲 Сгенерировать».

## 🔑 Как работают коды

Коды проверяет **сервер** (функция `redeem_code` в базе), а не браузер — их нельзя
подделать или обойти через F12. Коды создаёт тоже сервер (`generate_codes`):
формат `GEOT-7KQM-P3XA`, без похожих символов (0/O, 1/I/L), около 8·10¹¹ вариантов.
После 10 неверных попыток за час ввод блокируется — подобрать код нельзя.

| Тип | Когда использовать |
|---|---|
| **Личные** (каждый на 1 ученика) | Создайте сразу 25–30 штук на класс, раздайте по одному. Повторный ввод тем же учеником просто открывает курс. Видно, кто именно вошёл по какому коду. |
| **Один на группу** | Один код для всего класса; можно ограничить число мест. |

Для любого кода можно задать срок действия и подпись (класс, группа).

* **Ссылка-приглашение** (🔗): `…/platform/index.html?code=КОД`. Ученик открывает ссылку,
  входит по почте — и курс открывается сам, код вводить не нужно.
* **Карточки для печати** (🖨): после генерации — лист с кодами, чтобы разрезать и раздать.
* **👥 Кто вошёл** — список учеников по каждому коду.
* **⏸ Выключить** — код перестаёт работать, ученики остаются на курсе.
* **🚫 Отозвать** — код выключается, а все, кто вошёл по нему, теряют доступ.
* Ученик видит понятную причину отказа: кода нет / выключен / истёк / места закончились.

## 📚 Каталог курсов (только для администратора)

Вкладка **Каталог курсов** в `admin.html` открывается первой. В ней:
* все курсы, **включая скрытые черновики**, которых ученики не видят;
* по каждому курсу: число учеников, новые запросы, рабочие коды, загружен ли файл,
  дата последней записи;
* сводка сверху: курсов, учеников, ждущих ответа, рабочих кодов;
* поиск и фильтры (опубликованные / скрытые / без файла / с новыми запросами);
* действия: открыть, изменить, загрузить файлы, создать коды, скрыть / опубликовать.

Новый курс создаётся **черновиком** (скрыт): загрузите файл, проверьте и нажмите «👁 Опубликовать».

Данные каталога отдаёт только функция `admin_course_catalog` — ученику база вернёт пусто,
даже если он откроет `admin.html` напрямую. Преподаватель видит в каталоге только свои курсы.

### Вход через Google (по желанию)

Вход по ссылке на почту работает сразу. Для кнопки «Google» нужно один раз
настроить OAuth: **Authentication → Providers → Google** — там пошаговая инструкция Supabase
(создать OAuth Client в Google Cloud Console и вставить Client ID / Secret).

### Преподаватели

Чтобы другой человек вёл свой курс: он входит на сайт, а вы выполняете
```sql
update public.profiles set role = 'teacher' where email = 'его@почта';
```
Преподаватель видит панель управления, создаёт свои курсы, коды и одобряет запросы —
только по своим курсам.

## Что ещё не сделано

* Старые страницы курсов (`geotanu.html`, `geonish.html`) — один большой файл каждая.
  Ссылки внутри них на отдельные файлы (`maps/`, `nomenklatura/`, темы, тесты) при
  просмотре через `course.html` не откроются. Следующий шаг — разбить курс на уроки
  и хранить их в базе.
* Старый вход (`../index.html` + Google Таблица) продолжает работать параллельно,
  пока вы не переведёте учеников на новую платформу.
